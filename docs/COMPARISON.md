# Comparison: Baselines, the Proposed Hybrid, and Reviewed Prior Work

This document has two parts. **Part 1** is the model-versus-model comparison
(single-model baselines, hybrid architectures, the proposed hybrid) with the
extended metric suite. **Part 2** is the positioning against the reviewed
literature and the capability argument. Every number in Part 1 is copied from
`results/comparison/` (generated by `src/ml/compare.py`); nothing is rounded
in the proposed model's favour.

---

# Part 1 - Baselines vs. hybrids vs. the proposed model

## Protocol

- **Data:** GoEmotions simplified, 28 labels, multi-label. Test split: 5,427 comments.
- **One scorer for everything.** Every model writes only probabilities;
  `compare.py` computes all metrics. Per-label thresholds are tuned on the
  validation split and applied unchanged to test, for every model.
- **Seeds:** the from-scratch deep models, RoBERTa-base, and the RoBERTa-based
  hybrids use 3 seeds (42/43/44) and are reported as mean +/- std. BERT-base and
  the classical ML models are single-run (seed 42).
- **Uncertainty:** bootstrap 95% CIs and paired-bootstrap tests (300 resamples
  of the test rows). These use the **first seed** of each model (seed 42), so all
  models are resampled on identical rows. They capture test-sample noise, not
  training-seed noise.
- **Reproduce:** `src/ml/run_experiments.sh` (see the README).

## Models compared

| Family | Model | What it is |
|---|---|---|
| Classical ML | TF-IDF + Logistic Regression | One-vs-rest over word 1-2gram + char 2-5gram TF-IDF |
| Classical ML | TF-IDF + Linear SVM | Platt-calibrated for probabilities |
| Classical ML | TF-IDF + Naive Bayes | Multinomial NB |
| Classical ML | TF-IDF + Random Forest | Native multi-label |
| Hybrid ML | TF-IDF ML Ensemble | Soft vote over LR + SVM + RF (NB dropped by a validation PR-AUC quality floor) |
| Deep learning | TextCNN | Trained from scratch, 4 kernel sizes |
| Deep learning | BiLSTM | Trained from scratch |
| Hybrid DL | CNN-BiLSTM-Attention | Trained from scratch |
| Transformer | BERT-base (fine-tuned) | `[CLS]` head, 1 seed |
| Transformer | RoBERTa-base (fine-tuned) | `<s>` head; the original single-model baseline family |
| Hybrid (transformer + ML) | RoBERTa + TF-IDF ML fusion | Late fusion of RoBERTa probabilities with the ML ensemble |
| Hybrid (transformer + LSTM) | RoBERTa-BiLSTM-Attention | RoBERTa token states -> BiLSTM -> attention pool + max pool + `<s>` |
| **Proposed** | **RoBERTa-BiLSTM-Attn + TF-IDF ML** | **The neural hybrid above, late-fused with the TF-IDF ML ensemble** |

Fusion is `p = (1 - w) * p_neural + w * p_ml`, with one global `w` per seed
chosen on validation (grid 0.00-0.60). The chosen `w` is not stable across
seeds. For the proposed model it was 0.05, 0.50, 0.35 for seeds 42/43/44, with
validation macro-F1 gains over `w = 0` of only +0.0004, +0.0091, +0.0067. That
instability is itself a hint that the ML branch adds little consistent signal on
top of the BiLSTM head.

## Metric suite

| Group | Metrics |
|---|---|
| Threshold-based | Macro/micro/weighted/samples F1, macro precision, macro recall (= **sensitivity**), macro **specificity**, balanced accuracy, macro and micro **MCC**, macro **Cohen's kappa**, exact-match accuracy, top-1 accuracy, samples Jaccard, Hamming loss |
| Ranking / threshold-free | Macro and micro **AUC-ROC**, macro and micro **PR-AUC**, label-ranking average precision, coverage error, ranking loss |
| Probability quality | **Log loss**, Brier score, expected calibration error (15 bins) |
| Business level | Macro F1 and AUC-ROC over the 4 dashboard buckets |
| Cost | Parameters, training minutes, inference ms per 1k texts |
| Inference | Bootstrap CIs and paired-bootstrap significance on F1, MCC, AUC-ROC, PR-AUC |

Per-label sensitivity, specificity, MCC and kappa come from each label's
one-vs-rest confusion matrix and are macro-averaged over the 28 labels.

## Findings (strictly from the numbers above)

1. **A single classical model is a weak baseline, as the reviewer said.**
   Against all eight non-transformer baselines the proposed hybrid is better by
   +0.06 to +0.25 macro F1, +0.04 to +0.14 macro AUC-ROC and +0.09 to +0.28
   macro PR-AUC, every difference significant. The strongest classical result on
   macro F1 is the SVM (0.488); the ML ensemble leads on AUC-ROC (0.908) but does
   not beat the SVM on F1 (0.485 vs. 0.488).
2. **Almost all of that gain comes from the pretrained transformer encoder, not
   from the hybrid design.** Plain fine-tuned BERT-base (0.545) and RoBERTa-base
   (0.539) are already ~0.05-0.06 macro F1 above the best non-transformer model.
   The from-scratch deep models (TextCNN, BiLSTM, CNN-BiLSTM-Attention) do not
   beat the TF-IDF models.
3. **The proposed hybrid is not significantly better than the strongest
   transformer alternatives on threshold-based metrics.** Versus BERT-base,
   RoBERTa-base, RoBERTa-BiLSTM-Attention and RoBERTa + TF-IDF fusion, the macro-F1,
   micro-F1, MCC and PR-AUC deltas all have CIs that include zero.
4. **Where it does show an edge, the edge is small and in threshold-free
   ranking metrics:** macro AUC-ROC +0.005 over RoBERTa-base and +0.008 over
   RoBERTa-BiLSTM-Attention (both sig.). It also has the best micro AUC-ROC
   (0.9641), macro PR-AUC (0.5526), coverage error (2.391), ranking loss (0.0399)
   and log loss (0.0797). The margins over the runner-up are in the third or
   fourth decimal; the log-loss margin over the fusion model (0.0797 vs. 0.0800)
   is no larger than the seed std of either.
5. **It does not significantly beat the simpler RoBERTa + TF-IDF fusion.** The
   fusion model has the higher mean macro F1 (0.5519 vs. 0.5460), MCC and kappa,
   and the 3-seed macro AUC-ROC is a tie (0.9452 vs. 0.9451). The paired test
   finds no significant difference on any of the five tested metrics. The
   BiLSTM-attention head therefore has no demonstrated benefit once the TF-IDF
   branch is present. The component that appears to help is the **late fusion
   with TF-IDF** (RoBERTa-base macro F1 0.5389 -> 0.5519, macro AUC-ROC
   0.9406 -> 0.9452), while the BiLSTM head contributes nothing measurable on top.
   (Whether the fusion gain over plain RoBERTa is itself significant was not
   tested directly; it is not part of `significance.csv`.)
6. **Gains from the ML branch concentrate in rare labels** (3-seed mean
   per-label F1, RoBERTa-base -> RoBERTa + TF-IDF fusion): grief 0.458 -> 0.548,
   relief 0.341 -> 0.515, nervousness 0.398 -> 0.441, joy 0.631 -> 0.651. These
   labels have 6-161 test examples (grief 6, relief 11, nervousness 23), so the
   per-label numbers are noisy and were not individually tested.
7. **Cost.** The proposed model has 126.2M parameters (RoBERTa-base: 124.7M),
   trains in 14.3 min vs. 11.8 min per run (RTX 3060 6GB), and the neural forward
   pass costs about the same (0.40 vs. 0.43 ms per 1k texts as logged). The
   TF-IDF branch adds a CPU-side vectorise-and-score step whose inference time is
   not measured in `cost.csv`. TF-IDF models have ~3.5M parameters and train in
   under 2 minutes on CPU.
8. **Calibration.** All transformer variants are well calibrated (ECE
   0.004-0.006); RoBERTa-base alone has the best ECE (0.0042). Hybridisation does
   not improve it.

## Threats to validity

- **Seed vs. test-sample noise.** Significance tests resample test rows on the
  seed-42 run only. Seed std on macro F1 (0.004-0.008) is of the same order as
  several of the deltas, so "n.s." results are plausible ties, not proof of
  equivalence. Three seeds is too few for a formal seed-level test.
- **No multiple-comparison correction** across 12 comparisons x 5 metrics. The
  AUC-ROC "significant" edges (e.g. CI lower bound +0.0004 vs. RoBERTa-base) are
  suggestive only.
- **Single runs** for BERT-base and the classical ML models.
- **Two tuning steps on the validation split** for fusion models (per-label
  thresholds and the fusion weight).
- **Different training pipeline from the shipped model.** The deployed checkpoint
  `model-v1` came from the earlier `train_roberta.py` pipeline (max length 128,
  4 epochs, macro F1 0.475). The comparison above uses `train_transformer.py`
  (max length 64, separate head learning rate, early stopping on validation
  PR-AUC), whose RoBERTa-base reaches 0.539. The two RoBERTa numbers are not
  interchangeable, and the difference is not attributed to a single cause here.
- **The proposed hybrid is not a deployed checkpoint.** `train_transformer.py`
  saves probabilities only, so the API still serves `model-v1` (plain RoBERTa).
- **Domain.** All numbers are on GoEmotions (Reddit). No labelled product-review
  set exists, so none of this is a measurement on the deployment domain.

# Part 2 - Positioning against the reviewed literature

## Research Gap Identification

Synthesizing the limitations of the reviewed literature, the following gaps justify this project's design:

1. **No fine-grained + multi-label + explainable system combined.** GoEmotions (#1) provides the taxonomy but only benchmarks plain classifiers with no explainability. SHAP/LIME (#6, #7) provide explainability but are model-agnostic add-ons never integrated end-to-end with a fine-grained multi-label emotion classifier in a deployable product. The Acheampong survey (#8) confirms XAI-for-NLP techniques remain largely decoupled from production emotion/sentiment systems. **Gap:** an end-to-end pipeline that is simultaneously fine-grained, multi-label, and token-explainable.

2. **Single-corpus training limits generalization.** GoEmotions (#1) is Reddit-domain; CARER (#4) and DailyDialog (#5) are Twitter/dialogue-domain. Survey #8 explicitly flags poor cross-domain transfer as an open problem. No reviewed work combines multiple emotion corpora with a principled way to handle each corpus's partial label coverage. **Gap:** a masked multi-label loss that lets heterogeneous emotion corpora be combined for training without corrupting the label space with false negatives.

3. **Whole-document scoring hides mixed sentiment.** ABSA work (#12) addresses this at the aspect level but requires predefined aspect categories, which does not generalize to open emotion labels. No reviewed emotion-classification system does segment-level scoring for reviews. **Gap:** segment-level (not aspect-predefined) emotion scoring for arbitrary review text.

4. **Business actionability is absent from academic taxonomies.** The 27-label GoEmotions taxonomy (#1) is academically rigorous but not directly actionable by a business stakeholder. **Gap:** a mapping layer from fine-grained emotion labels to business-relevant categories (satisfaction, frustration, confusion, concern).

The deployed system - a RoBERTa multi-label classifier with SHAP token attribution, segment-level scoring, and a business-bucket rollup, with optional masked-loss multi-corpus training - addresses all four gaps. The hybrid architectures in Part 1 are an accuracy study layered on top of that system, and as Part 1 shows, they are not what delivers the advantage.

## On raw accuracy versus prior work

Published GoEmotions baselines report macro F1 of roughly 0.46-0.52 (Demszky et
al., 2020, BERT-base). Our numbers (Part 1) are in or slightly above that
range; this project does not claim a dramatic accuracy win over prior work.

## Capability comparison

| Capability | GoEmotions (#1) | BERT/RoBERTa (#2, #3) | SHAP/LIME (#6, #7) | ABSA (#12) | This project |
|---|---|---|---|---|---|
| 27+ label fine-grained emotion taxonomy | yes | no | no | no (fixed aspects) | yes |
| Multi-label (not single softmax) output | yes | - | - | no | yes |
| Token-level explainability integrated end-to-end | no | no | yes (generic, unintegrated) | no | yes (SHAP wired to classifier, served via `/explain`) |
| Multi-corpus training with partial label coverage handled correctly | no | no | no | no | yes (masked BCE loss) |
| Segment-level (mixed-sentiment) scoring | no | no | no | partial (fixed aspects only) | yes (dynamic segment splitting) |
| Business-actionable output (vs. academic label) | no | no | no | no | yes (4-bucket rollup) |
| Deployed, callable system (not notebook/benchmark only) | no | no | no | no | yes (FastAPI + React) |

No single reviewed paper checks more than two of these seven boxes at once. This project checks all seven. That combination, not a macro-F1 bump, is the actual contribution, and it is verifiable directly against the codebase (`src/ml/shap_explainer.py`, `src/ml/aux_datasets.py`, backend `/explain` and `/analyze` routes).

### Caveats a credible comparison must disclose

- `grief`, `pride`, `relief` scored 0.000 F1 in `model-v1` (under 20 test examples each). The newer pipeline in Part 1 gets non-zero F1 on them (3-seed means 0.46-0.55 for grief, 0.34-0.52 for relief), but with 6 and 11 test examples these are very noisy.
- No labelled product-review test set exists; all numbers are on GoEmotions (Reddit) test data.
- Part 1 uses 3 seeds for most neural models, but the historical table above is single-seed.

---

**Bottom line.** Against classical ML, from-scratch deep models, and hybrids of those, the transformer-based approach is a large and statistically significant improvement. Among transformer-based options, the proposed RoBERTa-BiLSTM-Attention + TF-IDF hybrid is competitive and best on a few threshold-free metrics by very small margins, but it is **not demonstrably better** than plain fine-tuned RoBERTa/BERT on F1, MCC or PR-AUC, and not better than the simpler RoBERTa + TF-IDF fusion. The defensible contribution is the end-to-end capability set (explainability, multi-corpus handling, segment scoring, business rollup, deployment) together with a well-instrumented, honest comparison, not a large accuracy win from the hybrid architecture.
